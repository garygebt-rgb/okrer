# Step 3: 对齐检查

**目标：** 检查用户草稿 OKR 与上级 OKR 的对齐关系，识别贡献型（我的产出有助于上级目标）和依赖型（我的目标需要他人先完成）两种对齐类型，覆盖直属上级和平级团队依赖。

**前置条件：** Step 2 已完成（SMART 验证结果）

**下一步：** Step 4 — 修改建议

## 输入

- 用户草稿 Objective 的标题和描述
- 用户的 objectiveId（用于查询对齐关系）
- 用户的 userID（用于查询其 OKR 周期）
- Step 2 的 SMART 验证结果（作为上下文参考）

## 执行步骤

### 1. 获取对齐关系数据

#### 1.1 查询已有对齐关系

调用 `lark-cli` 获取用户目标与上级/平级目标的已有对齐关系：

```
执行命令：lark-cli okr alignments --objective-id "{userObjectiveId}"
```

**预期输出：** JSON 数组，每个元素包含：
- `alignment_id` — 对齐关系 ID
- `type` — 对齐类型（`contributing` 或 `dependent`）
- `target_objective_id` — 目标 OKR 的目标 ID
- `target_objective_title` — 目标 OKR 的标题
- `target_owner_name` — 目标 OKR 的负责人姓名

**错误处理：**
- 若命令执行失败，显示：
  > 未能获取对齐关系数据。请确认你的 objectiveId 是否正确，或联系管理员确认你已创建目标。
- 若返回空数组，继续执行 1.2 进行兜底搜索。

#### 1.2 获取目标详情

对每个对齐关系中的 `target_objective_id`，调用：

```
执行命令：lark-cli okr objectives get --id "{targetObjectiveId}"
```

获取目标的完整信息（标题、描述、负责人、部门）。

#### 1.3 兜底搜索：无对齐关系时尝试查找上级目标

若 1.1 返回空数组，尝试自动查找用户的上级目标：

a. 获取用户当前周期的目标列表：
```
执行命令：lark-cli okr cycle-list --user-id "{userID}"
```

b. 从返回的周期数据中提取用户的部门信息，查找同部门更高级别（如主管、总监）的 OKR。

c. 若无法自动识别上级，提示用户：
> 未检测到系统记录的对齐关系。请手动确认以下两点：
> 1. 你的目标是否有助于上级的某个目标？
> 2. 你的目标是否依赖其他团队的某个目标？

#### 1.4 平级依赖搜索

基于用户目标的标题和描述中的关键词，搜索同周期内其他团队的目标：

```
执行命令：lark-cli okr cycle-detail --cycle-id "{currentCycleId}"
```

遍历返回的所有目标，使用关键词匹配（标题/描述中与用户目标相关的技术名词、项目名称、业务域）识别潜在的依赖关系。

### 2. 对齐关系分类

对每个找到的对齐关系，按照 D-08 的定义进行分类和输出：

#### 2.1 贡献型对齐（Contributing）

用户的产出直接贡献到上级或平级的目标达成。

**输出格式：**
```
**贡献型对齐**：你的目标「{用户的 objective title}」有助于 {target owner name} 的目标「{target objective title}」达成
追问建议：{具体的跟进问题}
```

**追问示例：**
- 「你计划如何量化对这个目标的贡献？」
- 「你的交付成果中，哪些指标可以直接反映对上级目标的推动？」
- 「你多久和 {target owner name} 同步一次进展？」

#### 2.2 依赖型对齐（Dependent）

用户的目标需要其他人或团队先完成他们的目标，才能继续推进。

**输出格式：**
```
**依赖型对齐**：你的目标「{用户的 objective title}」需要 {target owner name} 的「{target objective title}」完成后才能推进
追问建议：{具体的跟进问题}
```

**追问示例：**
- 「你是否和 {target owner name} 确认过他们的交付时间？」
- 「如果对方的交付延期，你的应急方案是什么？」
- 「你是否在目标描述中注明了这个依赖关系？」

### 3. 输出结构

#### 3.1 贡献型对齐列表

```
## 贡献型对齐

{序号}. **贡献型对齐**：你的目标「...」有助于 {name} 的目标「...」达成
   追问建议：...

{序号}. **贡献型对齐**：...
```

#### 3.2 依赖型对齐列表

```
## 依赖型对齐

{序号}. **依赖型对齐**：你的目标「...」需要 {name} 的「...」完成后才能推进
   追问建议：...

{序号}. **依赖型对齐**：...
```

#### 3.3 未覆盖的上级目标

检查是否有上级目标未与用户当前目标建立对齐关系：

```
## 未覆盖的上级目标

检测到以下上级目标与你的当前目标未建立对齐关系：

| 上级目标 | 负责人 | 建议 |
|---------|--------|------|
| {title} | {name} | 确认是否需要为此目标设定子目标 |
```

若没有未覆盖的上级目标，显示：
> 已覆盖所有检测到的上级目标。

#### 3.4 汇总表格

```
## 对齐检查汇总

| 对齐类型 | 数量 | 涉及目标 |
|---------|------|---------|
| 贡献型对齐 | {count} | {目标列表} |
| 依赖型对齐 | {count} | {目标列表} |
| 未覆盖上级 | {count} | {目标列表} |
```

### 4. 无对齐关系时的输出

若经过所有步骤仍未检测到任何对齐关系，显示：

```
## 对齐检查提示

未检测到对齐关系。建议手动确认：

1. 你的目标是否有助于上级的某个目标？
2. 你的目标是否依赖其他团队的某个目标？

若确认需要对齐，请在飞书 OKR 系统中手动建立对齐关系后重新检查。
```

### 5. 完整输出示例

```
## 对齐检查结果

### 贡献型对齐

1. **贡献型对齐**：你的目标「优化 CI/CD 流程」有助于上级目标「提升研发效率」达成
   追问建议：你计划如何量化对研发效率提升的贡献？例如构建时间缩短百分比、部署频率提升等。

2. **贡献型对齐**：你的目标「优化 CI/CD 流程」有助于架构组目标「统一技术基础设施」达成
   追问建议：你的 CI/CD 流程改造方案是否可以推广到其他团队使用？

### 依赖型对齐

1. **依赖型对齐**：你的目标「完成新版 API 上线」需要平级团队「前端重构」完成后才能对接
   追问建议：你是否和前端团队确认过他们的交付时间？如果前端重构延期，你的 API 能否先内部测试？

## 对齐检查汇总

| 对齐类型 | 数量 | 涉及目标 |
|---------|------|---------|
| 贡献型对齐 | 2 | 提升研发效率、统一技术基础设施 |
| 依赖型对齐 | 1 | 前端重构 |
| 未覆盖上级 | 0 | 已覆盖所有检测到的上级目标 |
```

## 数据类型引用

本步骤使用以下 `okr-shared` 类型和函数：

- `AlignmentType` — 对齐类型枚举：`CONTRIBUTING`（贡献型）、`DEPENDENT`（依赖型）（来自 `okr-types.ts`）
- `Alignment` — 对齐关系结构（来自 `okr-types.ts`）
- `Objective` — 目标结构（来自 `okr-types.ts`）
- `fetchAlignments()` — 获取对齐关系（来自 `data-collector.ts`）
- `fetchObjectives()` — 获取目标详情（来自 `data-collector.ts`）

对应的 CLI 命令：
- `lark-cli okr alignments --objective-id {id}` — 获取对齐关系
- `lark-cli okr objectives get --id {id}` — 获取目标详情

## 安全注意

- 仅展示用户有权限访问的对齐数据，通过 `lark-cli` 的权限模型自动过滤无权限目标（T-02-05）
- 平级关键词匹配搜索仅使用公开的标题和描述，不访问受限的详细内容

# OKR Goal Setting

辅助管理者确保OKR目标设定合理、上下级对齐清晰、符合SMART原则。不计算完整KPI评分，只辅助20%季度任务目标部分的目标设定。

## When to Use

USE this skill when:
- 设定新一季度的OKR目标，需要验证是否符合SMART原则
- 检查个人目标与直属上级OKR的贡献型对齐
- 识别跨团队/平级OKR的依赖型对齐关系
- 获取往期OKR完成度分析，了解目标设定习惯
- 生成修改建议并确认后再发布

## When NOT to Use

DON'T use this skill when:
- 计算完整KPI评分 (OKR只占KPI的20%，本Skill不计算评分)
- 单纯查询OKR数据 (直接使用飞书OKR功能查看)
- 查看他人OKR (仅处理用户自己的数据)

---

## Workflow Overview

本工作流采用用户主动逐步执行模式。每步完成后询问"是否继续下一步？"用户确认后才进入下一步。

| Step | Name | Description |
|------|------|-------------|
| 1 | 收集背景 | 自动获取历史OKR、岗位类型、往期分析 |
| 2 | SMART验证 | 5维度检查，输出通过/问题/建议 |
| 3 | 对齐检查 | 检查上下级+平级依赖关系 |
| 4 | 修改建议 | 综合SMART+对齐分析生成建议 |
| 5 | 用户确认 | 展示完整分析，获取确认后保存 |

---

## Step 1: 收集背景 (Collect Context)

自动获取用户历史OKR数据、岗位类型、往期分析，为后续SMART验证和对齐检查提供上下文。

### 获取OKR周期

飞书智能伙伴环境下使用飞书OKR API:

```
获取用户所有OKR周期 → 调用飞书OKR周期列表接口
获取周期详情 → 调用飞书OKR周期详情接口
```

输出字段: cycleId, name, startDate, endDate, status

### 岗位识别规则

| 部门关键词 | 岗位类型 |
|-----------|---------|
| 研发、开发、后端、前端、架构、运维 | 研发 |
| 产品、PM、产品经理 | 产品 |
| 测试、QA、质量 | 测试 |
| 管理、总监、经理、主管 | 管理 |

从OKR响应中提取部门信息，自动映射到岗位类型。若无法判断，询问用户确认。

### 历史分析指标

计算以下维度:

| 指标 | 说明 |
|------|------|
| 未完成目标数 | 得分 < 0.7 的目标数量 |
| 重复目标数 | 相似标题跨周期出现次数 |
| 平均得分 | 所有历史目标平均得分 |
| 设定习惯 | avg>0.8偏容易, avg<0.5偏保守, 0.5-0.8合理 |

### 错误处理

- 返回空数组: 提示"首次设定OKR，跳过历史分析"
- 命令失败: 提示确认数据访问权限

完成后询问: "是否继续到 Step 2 (SMART验证)？回复'继续'或提供你要验证的目标。"

---

## Step 2: SMART验证 (SMART Validate)

5维度检查每个目标，输出"通过/问题/建议" + 具体改写示例。

### SMART维度检查

| 维度 | 检查要点 | 判断标准 |
|------|----------|----------|
| Specific | 是否具体明确，不含模糊词 | 有明确动词、对象、范围 |
| Measurable | 是否有量化指标或完成标准 | 数字、百分比、时间节点 |
| Achievable | 是否考虑资源和时间可行性 | 参考历史完成率、团队规模 |
| Relevant | 是否与团队/公司目标相关 | 有上级OKR对齐或团队目标关联 |
| Time-bound | 是否有明确截止日期 | 季度/月度具体时间点 |

### 评分计算

SMART评分 = 通过维度数 / 5

每个维度输出:
- 结果: 通过/问题/建议
- 说明: 一句话解释原因
- 改写示例: 如果有问题，提供具体改写建议

完成后询问: "是否继续到 Step 3 (对齐检查)？"

---

## Step 3: 对齐检查 (Alignment Check)

检查两类对齐关系，标注"贡献型"vs"依赖型"。

### 贡献型对齐

个人目标向上贡献上级OKR:

```
查询上级OKR → 调用飞书OKR对齐关系接口
筛选贡献型对齐 → 检查是否覆盖上级关键目标
```

### 依赖型对齐

个人目标依赖平级/跨团队OKR:

```
查询平级OKR → 调用飞书OKR对齐关系接口
筛选依赖型对齐 → 标注依赖对象和依赖内容
```

### 对齐检查输出

| 对齐类型 | 数量 | 涉及目标 |
|---------|------|----------|
| 贡献型对齐 | n | 目标列表 |
| 依赖型对齐 | n | 目标列表 |
| 未覆盖上级 | n | 上级目标列表 |

**警告**: 如果存在"未覆盖上级目标"，需要提醒用户补充对齐。

完成后询问: "是否继续到 Step 4 (修改建议)？"

---

## Step 4: 修改建议 (Generate Suggestions)

综合SMART评分和对齐分析，生成修改建议。

### SMART改进建议表

| 维度 | 当前状态 | 改进建议 |
|------|----------|----------|
| Specific | 问题/建议 | 具体改写内容 |
| Measurable | 问题/建议 | 量化指标建议 |
| ... | ... | ... |

### 对齐改进建议

- 补充贡献型对齐: 建议添加对上级某某目标的贡献
- 标注依赖型对齐: 建议明确与某某团队的协作依赖

### 综合建议

基于历史模式给出建议:
- 若习惯偏容易: 建议设定更有挑战性的目标
- 若习惯偏保守: 建议设定更可行的目标
- 若有重复目标: 建议思考是否真正推动改进

完成后询问: "是否继续到 Step 5 (用户确认)？"

---

## Step 5: 用户确认 (Confirm)

展示完整分析结果，获取用户明确确认后保存目标。

### 展示内容

1. 原始目标: 标题、描述
2. 背景分析: 历史周期数、未完成目标、设定习惯、岗位类型
3. SMART验证: 5维度结果表、SMART评分
4. 对齐检查: 贡献型/依赖型/未覆盖统计
5. 修改建议: SMART改进、对齐改进、综合建议
6. 建议目标: 改进后的完整目标文本

### 确认选项

```
以上为完整的OKR目标设定分析结果。请选择：

1. 确认保存 — 将分析保存至本地，作为本季度OKR设定参考
2. 修改 — 告诉我要改哪个Objective或KR，帮你改写
3. 确认保存并更新我的OKR — 保存本地分析后，直接更新飞书线上OKR
4. 取消 — 放弃本次设定
```

### 处理各选项

**选项1 确认保存:**
保存分析报告至本地，工作流结束。

**选项2 修改:**
等待用户指定要修改的内容，输出改写版本后重新确认。

**选项3 保存并更新飞书OKR:**

```
更新飞书线上OKR → 调用飞书OKR写入API
更新目标标题和描述 → feishu-okr update-objective
```

更新结果表:
| 目标 | 状态 | 说明 |
|------|------|------|
| O1 | 已更新 | 标题和描述已更新 |

如API失败，保存本地报告并提示用户手动更新。

**选项4 取消:**
放弃本次设定，工作流结束。

### 安全要求

- 用户必须显式选择确认选项
- 不设默认值或超时自动保存
- 更新前展示完整建议目标供确认
- 更新仅写入用户有权限的数据

## Scoring System Note

OKR占KPI的20%，本Skill不计算完整KPI评分。评分体系如下(仅供参考):

| 维度 | 权重 | 说明 |
|------|------|------|
| 难度 | 40% | LLM综合评估 |
| 努力度 | 40% | 客观证据统计 |
| 完成度 | 20% | 飞书OKR系统score值 |

总分 = 难度x40% + 努力度x40% + 完成度x20%

最终评分由人类评审决定。

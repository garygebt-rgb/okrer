# OKR Goal Setting

辅助管理者确保OKR目标设定合理、上下级对齐清晰、符合SMART原则。飞书智能伙伴环境下自动识别用户身份和主管信息，检查上级/平级同期目标关联纠偏。不计算完整KPI评分，只辅助20%季度任务目标部分的目标设定。

## ⚠️ 安装检测与飞书CLI备用方案

### 飞书CLI安装检测

**执行Skill前必须检测飞书CLI是否已安装：**

```bash
# 检测飞书CLI是否安装
lark-cli --version
```

**如果未安装，引导用户安装：**

```
检测到飞书CLI未安装，需要先安装飞书CLI才能获取OKR数据。

安装步骤：
1. 安装飞书CLI: npm install -g @larksuite/cli
2. 安装Skills: npx skills add larksuite/cli -y -g
3. 初始化配置: lark-cli config init --new
4. 登录授权: lark-cli auth login --recommend

请按以上步骤安装后，重新运行本Skill。
```

### 数据获取策略：优先飞书智能伙伴，备用飞书CLI

**获取OKR数据时采用双策略：**

| 策略 | 执行顺序 | 说明 |
|------|----------|------|
| **优先策略** | 1 | 尝试使用飞书智能伙伴自身能力获取OKR信息 |
| **备用策略** | 2 | 如果优先策略失败，使用 `lark-cli` 命令获取 |

**具体执行逻辑：**

1. **尝试飞书智能伙伴自动获取：**
   ```
   请获取用户当前周期的OKR目标和KR详情。
   ```

2. **如果失败（返回错误或空数据），启用飞书CLI备用方案：**
   ```bash
   # 获取OKR周期列表
   lark-cli okr cycle-list

   # 获取周期详情
   lark-cli okr cycle-detail --cycle-id "{cycleId}"

   # 获取目标详情
   lark-cli okr objectives get --objective-id "{objectiveId}"

   # 获取关键结果
   lark-cli okr key_results get --key-result-id "{krId}"
   ```

3. **如果飞书CLI也失败：**
   ```
   无法获取OKR数据，请检查：
   1. 飞书CLI是否已安装并授权
   2. 是否有 okr:okr.period:readonly 和 okr:okr.content:readonly 权限
   3. 运行 lark-cli auth login --recommend 重新授权
   ```

## When to Use

USE this skill when:
- 设定新一季度的OKR目标，需要验证是否符合SMART原则
- 检查个人目标与直属上级OKR的贡献型对齐
- 识别跨团队/平级OKR的依赖型对齐关系
- **上级目标中分配的任务是否出现在自己的目标中（纠偏检查）**
- **平级目标中依赖我的内容是否出现在自己的目标中（纠偏检查）**
- 获取往期OKR完成度分析，了解目标设定习惯
- 生成修改建议并确认后再发布

## When NOT to Use

DON'T use this skill when:
- 计算完整KPI评分 (OKR只占KPI的20%，本Skill不计算评分)
- 单纯查询OKR数据 (直接使用飞书OKR功能查看)
- 查看他人OKR (仅处理用户自己的数据)

## ⚠️ 执行规则（CRITICAL）

**必须严格按以下顺序执行，禁止跳步或一次性输出所有内容：**

1. **Step 1 先执行** — 必须先展示背景收集结果（用户身份、历史OKR、主管信息），询问用户是否继续
2. **Step 2 次执行** — 用户确认后才执行SMART验证，展示结果后询问是否继续
3. **Step 3 再执行** — 用户确认后才执行对齐纠偏检查（含上级/平级目标纠偏），展示结果后询问是否继续
4. **Step 4 后执行** — 用户确认后才生成修改建议，展示结果后询问是否继续
5. **Step 5 最后执行** — 用户确认后才展示完整分析，等待用户选择确认选项

**每步执行后必须：**
- 展示该步骤的完整输出结果
- 明确询问用户："是否继续到 Step N？"
- 等待用户回复后才进入下一步

**禁止行为：**
- 禁止一次性输出SMART+对齐+建议所有内容
- 禁止跳过任意步骤
- 禁止在用户未确认前自动进入下一步

## Workflow Overview

本工作流采用用户主动逐步执行模式。**严格执行5步顺序，每步完成后询问"是否继续下一步？"用户确认后才进入下一步。**

| Step | Name | Description | 必须展示内容 |
|------|------|-------------|--------------|
| 1 | 收集背景 | **自动识别用户身份**，获取历史OKR、岗位类型、主管信息 | 用户身份表、历史分析表、主管/平级信息表 |
| 2 | SMART验证 | 5维度检查（**Relevant维度引入上级/平级目标纠偏结果**） | SMART验证结果表、纠偏详情表 |
| 3 | 对齐纠偏 | **上级/平级同期目标关联纠偏** + 传统对齐检查 | 上级任务纠偏表、平级依赖纠偏表、未覆盖清单 |
| 4 | 修改建议 | 综合SMART+对齐+纠偏分析生成建议 | SMART改进表、纠偏新增目标列表 |
| 5 | 用户确认 | 展示完整分析，获取确认后保存 | 完整分析报告、4个确认选项 |
| 5 | 用户确认 | 展示完整分析，获取确认后保存 |

**飞书智能伙伴环境下自动识别用户身份**，无需用户提供 userID。

```

获取平级同事列表 → 同部门同级别同事的 open_id 列表
```

## Step 2: SMART验证 (SMART Validate)

**⚠️ 直接使用 Step 1 获取的目标/KR 进行 SMART 验证，无需用户再次提供目标。**

本步骤对 Step 1 获取的每个目标逐个进行 5 维度检查，输出"通过/问题/建议" + 具体改写示例。

**重要**: Relevant 维度检查会引入 Step 3 的上级/平级目标纠偏结果。

### SMART维度检查

| 维度 | 检查要点 | 判断标准 |
|------|----------|----------|
| Specific | 是否具体明确，不含模糊词 | 有明确动词、对象、范围 |
| Measurable | 是否有量化指标或完成标准 | 数字、百分比、时间节点 |
| Achievable | 是否考虑资源和时间可行性 | 参考历史完成率、团队规模 |
| **Relevant** | **是否与上级/团队目标相关 + 上级分配任务是否覆盖** | **有上级OKR对齐 + 上级目标中的任务分配已覆盖** |
| Time-bound | 是否有明确截止日期 | 季度/月度具体时间点 |

### Relevant 维度增强检查

Relevant 维度不仅检查"与团队/公司目标相关"，还要检查：

**上级分配任务覆盖检查**:
```
分析主管OKR目标描述 → 提取涉及用户的任务分配
匹配用户自己的目标 → 检查是否已覆盖主管分配的任务
输出纠偏建议 → 未覆盖的任务需要补充到用户目标中
```

**示例场景**:
```
主管OKR目标: "推进XX项目，张三负责后端开发，王五负责前端"
用户张三的目标: "优化系统性能"、"完善API文档"
纠偏结果: 主管分配的"XX项目后端开发"未出现在张三目标中 → Relevant维度标记为"问题"
```

### 平级依赖检查（Relevant维度辅助）

```
分析平级OKR目标描述 → 提取"需要张三配合"、"依赖张三"等依赖声明
匹配用户自己的目标 → 检查是否已覆盖平级依赖的内容
输出纠偏建议 → 未覆盖的依赖需要补充到用户目标中
```

### 评分计算

SMART评分 = 通过维度数 / 5

每个维度输出:
- 结果: 通过/问题/建议
- 说明: 一句话解释原因
- 改写示例: 如果有问题，提供具体改写建议

### SMART验证输出示例

```
## SMART验证结果

目标: "优化系统性能"

| 维度 | 结果 | 说明 |
|------|------|------|
| Specific | 问题 | "优化"过于模糊，建议改为"将响应时间降低50%" |
| Measurable | 问题 | 缺少量化指标，建议添加"响应时间<200ms" |
| Achievable | 通过 | 参考历史完成率0.72，目标可行 |
| **Relevant** | **问题** | **主管分配的"XX项目后端开发"未覆盖** |
| Time-bound | 建议 | 建议添加"Q2结束前完成" |

SMART评分: 2/5

### Relevant维度纠偏详情

主管OKR中涉及你的任务分配:
- "XX项目后端开发" → **未出现在你的目标中**
- "API接口优化" → 已在你的目标"完善API文档"中覆盖

纠偏建议: 补充目标"完成XX项目后端开发，实现核心功能模块"

### 平级依赖检查

平级王五OKR中的依赖声明:
- "依赖张三提供API文档" → 已在你的目标中覆盖
- "需要张三配合联调" → **未出现在你的目标中**

纠偏建议: 在"完成XX项目后端开发"中添加"配合前端联调"
```

完成后询问: "是否继续到 Step 3 (对齐纠偏)？"

## Step 3: 对齐纠偏 (Alignment Check & Deviation Correction)

**⚠️ 必须执行：上级/平级同期目标关联纠偏**

**本步骤必须输出以下内容，缺一不可：**
1. 上级目标任务分配纠偏表（含未覆盖清单）
2. 平级目标依赖纠偏表（含未覆盖清单）
3. 传统对齐检查结果表
4. 综合纠偏建议（需补充的目标/KR列表）

**如果上级/平级OKR中未发现涉及用户的内容，必须明确说明"未发现纠偏项"，而不是跳过该检查。**

---

### 纠偏检查流程

#### 1. 上级目标任务分配纠偏

检查主管OKR中是否有涉及用户但用户目标未覆盖的内容：

```
分析主管当前周期OKR目标 → 遍历每个目标的描述和KR
提取涉及用户的任务分配 → 搜索用户姓名、"负责"、"由XX完成"等关键词
对比用户自己的目标 → 检查是否已覆盖主管分配的任务
输出未覆盖清单 → 列出需要补充的任务
```

**自然语言调用示例**:
```
请分析主管 {managerName} 的OKR目标：
提取所有涉及用户 {userName} 的任务分配。
返回 任务内容、所属目标、关键词匹配结果。

请对比用户 {userName} 的OKR目标：
检查主管分配的任务是否已出现在用户目标中。
返回 未覆盖的任务清单。
```

#### 2. 平级目标依赖纠偏

检查平级同事OKR中是否有依赖用户但用户目标未覆盖的内容：

```
分析平级同事当前周期OKR → 遍历每位同事的目标描述和KR
提取依赖用户的声明 → 搜索"依赖XX"、"需要XX配合"、"等XX完成"等关键词
对比用户自己的目标 → 检查是否已覆盖平级依赖的内容
输出未覆盖清单 → 列出需要补充的协作任务
```

**自然语言调用示例**:
```
请分析平级同事 {colleagueNames} 的OKR目标：
提取所有依赖用户 {userName} 的声明。
返回 依赖内容、声明者、关键词匹配结果。

请对比用户 {userName} 的OKR目标：
检查平级依赖的内容是否已出现在用户目标中。
返回 未覆盖的依赖清单。
```

### 传统对齐检查

#### 贡献型对齐

个人目标向上贡献上级OKR:

```
查询上级OKR → 调用飞书OKR对齐关系接口
筛选贡献型对齐 → 检查是否覆盖上级关键目标
```

#### 依赖型对齐

个人目标依赖平级/跨团队OKR:

```
查询平级OKR → 调用飞书OKR对齐关系接口
筛选依赖型对齐 → 标注依赖对象和依赖内容
```

### Step 3 输出示例

```
## 对齐纠偏检查结果

### 上级目标任务分配纠偏

主管OKR分析: 李四（技术总监）2026-Q2

| 主管目标 | 涉及你的任务 | 你的目标覆盖情况 | 纠偏建议 |
```

## Step 4: 修改建议 (Generate Suggestions)

综合SMART评分、对齐分析和纠偏检查结果，生成修改建议。

### SMART改进建议表

| 维度 | 当前状态 | 改进建议 |
|------|----------|----------|
| Specific | 问题/建议 | 具体改写内容 |
| Measurable | 问题/建议 | 量化指标建议 |
| Achievable | 通过 | 无需修改 |
| Relevant | 问题 | **补充上级分配任务和平级依赖内容** |
| Time-bound | 建议 | 添加截止日期 |

### 纠偏改进建议

基于 Step 3 的纠偏结果，给出具体建议:

- **上级任务纠偏**: 建议新增目标覆盖主管分配的"XX项目后端开发"、"API重构"
- **平级依赖纠偏**: 建议在相关目标中添加"配合前端联调"、"完成数据接口"

### 对齐改进建议

- 补充贡献型对齐: 建议添加对上级某某目标的贡献
- 标注依赖型对齐: 建议明确与某某团队的协作依赖

### 综合建议

基于历史模式给出建议:
- 若习惯偏容易: 建议设定更有挑战性的目标
- 若习惯偏保守: 建议设定更可行的目标
- 若有重复目标: 建议思考是否真正推动改进

### 建议目标改写示例

```
## 原始目标 → 建议改写

原始目标: "优化系统性能"
改写建议: "将系统响应时间降低50%，Q2结束前完成，配合XX项目后端开发"

### 纠偏新增目标

1. 新增: "完成XX项目后端开发，实现核心功能模块，配合前端联调"
2. 新增: "完成API重构，优化接口性能，供赵六使用数据接口"
```

完成后询问: "是否继续到 Step 5 (用户确认)？"

## Step 5: 用户确认 (Confirm)

展示完整分析结果，获取用户明确确认后保存目标。

### 展示内容

1. 原始目标: 标题、描述
2. 背景分析: 历史周期数、未完成目标、设定习惯、岗位类型
3. SMART验证: 5维度结果表、SMART评分、Relevant纠偏详情
4. 对齐纠偏: 上级任务纠偏、平级依赖纠偏、传统对齐检查
5. 修改建议: SMART改进、纠偏改进、对齐改进、综合建议
6. 建议目标: 改进后的完整目标文本 + 纠偏新增目标

### 确认选项

```
以上为完整的OKR目标设定分析结果。请选择：

1. 确认保存 — 将分析保存至本地，作为本季度OKR设定参考
2. 修改 — 告诉我要改哪个Objective或KR，帮你改写
3. 确认保存并更新我的OKR — 保存本地分析后，直接更新飞书线上OKR
4. 取消 — 放弃本次设定
```

### 处理各选项

**选项1 确认保存:**
保存分析报告至本地，工作流结束。

**选项2 修改:**
等待用户指定要修改的内容，输出改写版本后重新确认。

**选项3 保存并更新飞书OKR:**

```
更新飞书线上OKR → 调用飞书OKR写入API
更新目标标题和描述 → feishu-okr update-objective
新增纠偏目标 → feishu-okr create-objective（如果需要）
```

更新结果表:
| 目标 | 操作 | 说明 |
|------|------|------|
| O1 | 已更新 | 标题和描述已更新 |
| O2 | 新增 | 纠偏新增目标 |

如API失败，保存本地报告并提示用户手动更新。

**选项4 取消:**
放弃本次设定，工作流结束。

### 安全要求

- 用户必须显式选择确认选项
- 不设默认值或超时自动保存
- 更新前展示完整建议目标供确认
- 更新仅写入用户有权限的数据

## Scoring System Note

OKR占KPI的20%，本Skill不计算完整KPI评分。评分体系如下(仅供参考):

| 维度 | 权重 | 说明 |
|------|------|------|
| 难度 | 40% | LLM综合评估 |
| 努力度 | 40% | 客观证据统计 |
| 完成度 | 20% | 飞书OKR系统score值 |

总分 = 难度x40% + 努力度x40% + 完成度x20%

最终评分由人类评审决定。

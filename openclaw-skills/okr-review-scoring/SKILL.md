# OKR Review Scoring

实现期末OKR评审评分，**整合多源证据**：周报内容（来自 okr-weekly-tracker）、手动案例链接、飞书活动记录自动扫描、人效月报表数据。解析用户自述文档(含截图)，验证证据，计算评分，生成评审报告。不计算完整KPI评分，只提供评分建议供人类参考。

## ⚠️ Init 命令（必须先执行）

**执行本 Skill 前必须先运行 init 命令进行环境检测和初始化：**

```
/okr-review-init
```

或自然语言：
```
帮我初始化OKR评审评分环境
```

| 8 | 当前OKR周期获取 | 获取待评审周期的目标/KR/指标 | 提示确认周期 |
| 9 | 周报文档搜索 | 搜索周期内的周报文档 | 标记"周报未生成" |

## When to Use

USE this skill when:
- 期末评审OKR完成情况，需要收集多源证据
- **整合每周自动生成的周报内容作为进展证据**
- 手动上传案例链接补充证据
- **自动扫描飞书活动记录（文档/会议/聊天）作为佐证**
- **参考人效月报表数据作为客观指标**
- 解析用户自述文档中的非结构化内容(文字、表格、截图、OKR卡片)
- 计算评分: 难度40% + 努力度40% + 完成度20%，按岗位权重
- 生成评审报告: 评分结果、证据清单、优势不足、往期对比、下季度建议

## When NOT to Use

DON'T use this skill when:
- 过程跟进提醒 (使用 okr-weekly-tracker Skill)
- 设定新OKR目标 (使用 okr-goal-setting Skill)
- 查看他人OKR评审 (仅处理用户自己的数据)

## 证据来源架构

本 Skill 整合**四类证据来源**，全面支撑OKR评审：

| 证据来源 | 采集方式 | 用途 | 权重参考 |
|----------|----------|------|----------|
| **周报内容** | 自动读取 okr-weekly-tracker 生成的周报 | 进展证据主体 | 努力度40% |
| **手动案例链接** | 用户手动上传补充 | 关键产出佐证 | 努力度40% |
| **飞书活动记录** | 自动扫描文档/会议/聊天记录 | 活跃度佐证 | 努力度40% |
| **人效月报表** | 自动读取PMO云文档 | 客观效率指标 | 努力度40%补充 |

## Workflow Overview

本工作流采用用户主动逐步执行模式。每步完成后询问"是否继续下一步？"

| Step | Name | Description |
|------|------|-------------|
| 1 | 材料收集 | 获取自述文档 + **读取周报历史** + **手动案例链接上传** |
| 2 | 数据验证 | **飞书活动自动扫描** + **人效月报表读取** + 周报数据解析 |
| 3 | 证据匹配 | 多源证据整合匹配，5维度验证 |
| 4 | 评分计算 | 应用难度40%+努力度40%+完成度20%公式 |
| 5 | 自述文档解析 | 深度解析非结构化文档，截图识别 |
| 6 | 报告生成 | 输出评分结果、多源证据清单、优势不足、往期对比、建议 |

## Step 1: 材料收集 (Material Collect)

获取用户自述文档链接、**读取周报历史**、**手动案例链接上传**。

### 1.1 自动读取周报历史

**飞书智能伙伴环境下自动读取 okr-weekly-tracker 生成的周报**：

```
识别当前周期 → 获取OKR周期ID
搜索周报文档 → 搜索标题包含"OKR周报"且时间范围在周期内的飞书文档
读取周报内容 → 解析每周周报，提取活动汇总、OKR进展详情
汇总周报数据 → 整合周期内所有周报的进展记录
```

**自然语言调用示例**:
```
请搜索飞书文档中标题包含"OKR周报"且创建时间在 {startDate} 至 {endDate} 之间的文档。
返回 文档token、标题、创建时间、内容摘要。

请读取这些周报文档的内容：
提取 每周活动汇总、OKR进展详情、本周亮点。
整合输出 周期内所有周报的进展记录汇总。
```

### 周报数据结构

| 字段 | 说明 |
|------|------|
| 周报日期 | 周报对应的日期范围 |
| 活动汇总 | 本周飞书文档/会议/聊天活动数 |
| OKR进展 | 各KR的进展状态（有进展/无进展） |
| 进展详情 | 具体活动内容描述 |

### 1.2 手动案例链接上传

用户可手动上传补充案例链接：

```
提示用户上传 → "请提供需要补充的案例链接（飞书文档、会议纪要、外部链接等）"
解析链接类型 → 识别飞书文档/飞书会议/外部链接
验证链接有效性 → 检查链接是否可访问
记录案例信息 → 提取标题、创建者、时间、内容摘要
```

**用户输入格式**:
```

- 飞书文档: https://xxx.feishu.cn/docx/xxxxx
- 会议纪要: https://xxx.feishu.cn/minutes/xxxxx
- 外部链接: https://github.com/xxx/xxx
```

### 1.3 用户自述文档

用户提供期末自述文档链接（飞书文档URL）：

```

获取文档基本信息 → 提取标题、创建者、更新时间
```

## Step 2: 数据验证 (Data Validate)

**飞书活动自动扫描** + **人效月报表读取** + 周报数据解析。

### 2.1 飞书活动记录自动扫描

自动扫描周期内用户在飞书中的所有活动，作为周报和手动案例的佐证：

```
扫描飞书文档 → 搜索用户创建/编辑的文档
扫描飞书会议 → 搜索用户参与的会议纪要
扫描飞书聊天 → 搜索用户发送的相关群聊/私聊消息
```

**自然语言调用示例**:
```
请搜索 {startDate} 至 {endDate} 期间我创建或编辑的飞书文档。
返回 文档token、标题、更新时间、编辑次数。

请搜索 {startDate} 至 {endDate} 期间我参与的会议纪要。
返回 会议标题、minute_token、参会人员、关键议题。

请搜索 {startDate} 至 {endDate} 期间我发送的群聊消息（关键词: 项目、目标、进展）。
返回 群聊名称、消息内容摘要、发送时间。
```

## Step 3: 证据匹配 (Evidence Match)

**多源证据整合匹配**，5维度验证。

### 证据来源整合

整合四类证据来源，按KR进行匹配：

| 证据来源 | 匹配方式 | 权重参考 |
|----------|----------|----------|
| 周报内容 | 关键词匹配KR标题 | 努力度主体证据 |
| 手动案例 | 用户指定关联KR | 关键产出证据 |
| 飞书活动 | 关键词匹配KR标题 | 活跃度佐证 |
| 人效月报 | 按岗位类型映射 | 客观指标佐证 |

### 5维度匹配验证

| 维度 | 检查内容 | 判断标准 |
|------|----------|----------|
| 可访问性 | URL是否有效 | 能成功获取内容 |
| 创建者 | 是否用户创建或参与 | 用户名出现在创建/编辑列表 |
| 时间范围 | 是否在周期内 | 创建/更新时间在周期范围内 |
| 关键词相关性 | 是否与KR相关 | 内容包含KR关键词 |
| 数据一致性 | 是否与自述/周报一致 | 多源数据交叉验证一致 |

### 多源证据匹配矩阵

对于每个KR，整合四类证据：

```
KR: 完成XX功能开发

周报证据:
- Week1: 参与XX功能设计会议 → 匹配 ✓
- Week3: 编写技术文档 → 匹配 ✓
- Week5: 提交代码PR → 匹配 ✓

手动案例证据:
- 飞书文档: XX功能设计文档 → 匹配 ✓
- GitHub链接: PR#123 → 匹配 ✓

飞书活动佐证:
- 文档编辑: XX功能相关文档8次编辑 → 佐证 ✓
```

## Step 4: 评分计算 (Score Calc)

应用难度40% + 努力度40% + 完成度20%公式，按岗位权重计算。

**努力度评分引入多源证据**：

### 评分维度

| 维度 | 权重 | 评估方式 |
|------|------|----------|
| 难度 | 40% | LLM综合评估(技术复杂度/资源投入/时间压力/创新性/跨部门协作) |
| **努力度** | 40% | **多源证据综合评分**：周报进展频率 + 手动案例质量 + 飞书活动活跃度 + 人效月报指标 |
| 完成度 | 20% | 飞书OKR系统KR最终score值(0-1范围) |

### 努力度评分公式（多源证据）

```
努力度 = 周报进展频率(40%) + 手动案例质量(30%) + 飞书活动活跃度(20%) + 人效月报指标(10%)

周报进展频率 = 有进展周数 / 总周数
手动案例质量 = 案例匹配度评分 (强匹配=1, 中匹配=0.7, 弱匹配=0.5)
飞书活动活跃度 = 活动数 / 周期平均活动数 (归一化到0-1)
人效月报指标 = 指标值 / 部门平均值 (归一化到0-1)
```

### 难度评估

LLM综合判断5个因素:
1. 技术复杂度: 是否涉及新技术、架构改造
2. 资源投入: 团队规模、预算支持
3. 时间压力: 是否有紧迫截止日期
4. 创新性: 是否首创或突破性工作
5. 跨部门协作: 是否涉及多团队协调

评分: 0-1分

### 完成度评估

直接取飞书OKR系统KR最终score值。

评分: 0-1分

### 总分计算

```
总分 = 难度 x 0.4 + 努力度 x 0.4 + 完成度 x 0.2
```

### 岗位权重

不同岗位可调整努力度计算权重：

| 岗位 | 周报权重 | 案例权重 | 活动权重 | 人效权重 |
|------|----------|----------|----------|----------|
| 研发 | 40% | 30% | 20% | 10% |
| 产品 | 40% | 35% | 15% | 10% |
| 测试 | 50% | 25% | 15% | 10% |
| 管理 | 35% | 40% | 15% | 10% |

### Step 4 输出示例


## 与 okr-weekly-tracker 的关联

本 Skill 依赖 `okr-weekly-tracker` 生成的周报内容作为主要证据来源。

**周报数据格式要求**：
- 周报标题包含"OKR周报"和用户姓名
- 周报内容包含"活动汇总"、"OKR进展详情"、"本周亮点"
- 周报存储在飞书文档中，便于本 Skill 读取

**如用户未使用 okr-weekly-tracker**：
- Step 1 周报读取结果为空
- 努力度评分仅依赖手动案例、飞书活动、人效月报
- 提示用户考虑使用 okr-weekly-tracker 进行过程跟踪

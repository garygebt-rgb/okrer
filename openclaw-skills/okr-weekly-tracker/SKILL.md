# OKR Weekly Tracker

员工自助安装的OKR周报自动化工具。安装后执行一次 `init` 命令，系统自动建立定时任务，每周扫描飞书活动、关联OKR进展、生成周报、尝试更新OKR、发邮件给PMO。全程自动化，无需每周手动触发。

## When to Use

USE this skill when:
- 作为员工，想要自动跟踪自己的OKR进展，不想每周手动写周报
- 想要本周飞书活动（文档、会议、聊天）自动关联到OKR目标
- 想要周报自动沉淀，OKR进展自动更新（如果可行）
- 想要周报概要自动发邮件给 ITPMO@homeinns.com
- 只需执行一次 init，后续全自动运行

## When NOT to Use

DON'T use this skill when:
- 想要手动控制每周周报内容（使用手动周报功能）
- 想要查看他人OKR进展（仅处理自己的数据）
- 想要期末评审评分（使用 okr-review-scoring Skill）
- 想要设定新OKR目标（使用 okr-goal-setting Skill）

## 安装与初始化

### Step 1: 安装 Skill

用户在飞书智能伙伴中安装此 Skill。

### Step 2: 执行 Init 命令

用户发送一条命令：

```
/okr-weekly-init
```

或自然语言：

```
帮我初始化OKR周报自动跟踪
```

### Init 命令执行内容

Init 命令会自动完成以下设置：

| 序号 | 设置项 | 说明 |
|------|--------|------|
| 1 | 识别用户身份 | 获取用户的 open_id、姓名、部门、岗位 |
| 2 | 获取当前OKR周期 | 识别活跃的OKR周期及其目标/KR列表 |
| 3 | 配置扫描范围 | 文档、会议纪要、群聊消息、私聊消息 |
| 4 | 建立定时任务 | 每周五下午17:00自动执行扫描 |
| 5 | 配置邮件接收方 | ITPMO@homeinns.com |
| 6 | 生成配置摘要 | 展示给用户确认 |

### Init 输出示例

```
## OKR周报自动跟踪已初始化

### 用户信息
- 姓名: 张三
- 部门: 技术部-研发中心
- 岗位: 后端开发

### 当前OKR周期
- 周期: 2026-Q2
- 目标数: 3个
- KR数: 8个

### 定时任务
- 执行时间: 每周五 17:00
- 扫描范围: 本周飞书活动（文档、会议、聊天）

### 邮件配置
- 收件人: ITPMO@homeinns.com
- 发送方式: 周报概要（周五执行后自动发送）

### 确认初始化成功？
回复"确认"开始自动跟踪，或"取消"放弃设置。
```

## 自动化执行流程

每周五17:00，系统自动执行以下流程：

### Phase 1: 扫描本周飞书活动

自动扫描本周（周一至周五）用户在飞书中的所有活动：

| 数据源 | 扫描内容 | 关联方式 |
|--------|----------|----------|
| 飞书文档 | 用户创建/编辑的文档 | 标题关键词匹配OKR目标 |
| 飞书会议 | 用户参与的会议纪要 | 会议主题关键词匹配 |
| 群聊消息 | 用户发送的消息 | 消息内容关键词匹配 |
| 私聊消息 | 与同事的讨论记录 | 消息内容关键词匹配 |

### 扫描命令示例

飞书智能伙伴环境下：

```
扫描本周飞书活动 → 自动调用飞书搜索API

文档扫描:
请搜索本周我创建或编辑的飞书文档，返回 title, url, update_time, content_summary。
按关键词匹配我的OKR目标，返回匹配结果。

会议扫描:
请搜索本周我参与的会议纪要，返回 meeting_title, minute_token, participants, key_topics。
按关键词匹配我的OKR目标，返回匹配结果。

聊天扫描:
请搜索本周我发送的群聊和私聊消息（关键词: 项目、目标、进展），返回 chat_name, message_content, timestamp。
按关键词匹配我的OKR目标，返回匹配结果。
```

### Phase 2: 关联OKR进展

将扫描结果与用户的OKR目标/KR进行关键词匹配：

| KR | 关键词 | 匹配活动 | 进展推断 |
|----|--------|----------|----------|
| KR1: 完成XX功能开发 | XX功能, 开发, 代码 | 文档A, 会议B, 提交C | 有进展 |
| KR2: 优化YY性能 | YY, 性能, 优化 | 会议D, 聊天记录E | 有进展 |
| KR3: 协调ZZ项目 | ZZ, 协调, 项目 | 会议F, 群聊G | 有进展 |

### 关联算法

```
对于每个KR:
  1. 提取KR标题关键词
  2. 搜索本周活动是否包含关键词
  3. 计算匹配度（活动数量 × 关词匹配权重）
  4. 判断进展状态：
     - 匹配活动>=3 → 有显著进展
     - 匹配活动1-2 → 有进展
     - 匹配活动=0 → 无进展或未更新
```

### Phase 3: 生成周报

基于扫描和关联结果，生成本周OKR进展周报：

```
## OKR周报 {日期范围}

员工: {userName}
周期: {cycleName}
生成时间: {timestamp}

### 本周活动汇总

| 数据源 | 活动数 | 关联OKR数 |
|--------|--------|----------|
| 飞书文档 | {n} | {m} |
| 飞书会议 | {n} | {m} |
| 群聊消息 | {n} | {m} |
| 私聊消息 | {n} | {m} |

### OKR进展详情

| 目标 | KR | 本周活动 | 进展状态 |
|------|----|---------|---------|
| O1 | KR1 | {活动列表} | 有进展 |
| O1 | KR2 | {活动列表} | 有进展 |
| O2 | KR3 | 无匹配活动 | 无进展 |

### 本周亮点

{基于活动内容生成的亮点摘要}

### 下周计划建议

{基于OKR进度生成的下周计划建议}

### 数据来源

- 飞书文档: {文档列表}
- 飞书会议: {会议列表}
- 飞书聊天: {聊天记录摘要}
```

### Phase 4: 尝试更新OKR进展

如果飞书OKR API支持写入，尝试自动更新KR进展备注：

```
尝试写入OKR进展 → 调用飞书OKR写入API

对于每个有进展的KR:
  生成进展备注内容（基于本周活动摘要）
  尝试调用 feishu-okr update-kr-note API
  如果成功 → 记录更新成功
  如果失败 → 记录失败原因（权限不足/API不支持）
```

### 更新内容示例

```
KR进展备注更新：

KR1: 完成XX功能开发
本周进展: 参与XX功能设计会议(周二)，编写技术文档(周三)，提交代码PR(周四)
更新状态: 成功

KR2: 优化YY性能
本周进展: 性能测试会议(周一)，编写优化方案文档(周二)
更新状态: 成功

KR3: 协调ZZ项目
本周进展: ZZ项目周会(周三)，群聊讨论进度(周四)
更新状态: API不支持写入
```

### Phase 5: 发送邮件给PMO

使用飞书邮箱发送周报概要邮件：

```
发送邮件 → 调用飞书邮件发送API

收件人: ITPMO@homeinns.com
主题: 【OKR周报】{userName} {日期范围}
正文: 周报概要（包含本周活动汇总、OKR进展详情、下周计划建议）
```

用户可随时查看定时任务状态：

```
/okr-weekly-status
```

输出：
```

```

## 飞书API调用

### 所需权限

| 权限 | 用途 |
|------|------|
| `okr:okr.period:readonly` | 读取OKR周期 |
| `okr:okr.content:readonly` | 读取OKR目标/KR |
| `okr:okr.progress:write` | 写入KR进展备注（可选） |
| `docs:document:readonly` | 搜索飞书文档 |
| `vc:minute:readonly` | 搜索会议纪要 |
| `im:message:readonly` | 搜索聊天记录 |
| `mail:send` | 发送邮件 |

### API调用示例

飞书智能伙伴环境下自然语言调用：

```
# 文档搜索
请搜索本周我创建或编辑的飞书文档，返回 title, url, update_time

# 会议纪要搜索
请搜索本周我参与的会议纪要，返回 meeting_title, minute_token, key_topics

# 聊天记录搜索
请搜索本周我发送的群聊消息，关键词包含我的OKR目标，返回 chat_name, message_content

# OKR进展写入（如果支持）
请更新我的KR进展备注，KR-ID为xxx，备注内容为xxx

# 邮件发送
请发送邮件给 ITPMO@homeinns.com，主题为【OKR周报】xxx，正文为xxx
```

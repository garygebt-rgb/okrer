# OKRskill 需求文档

> 创建时间: 2026-04-21
> 状态: 待确认

## v1 需求

### 共享数据层 (SHARED)

- [ ] **SHARED-01**: 共享模块目录结构 (`okr-shared/`) 包含 SKILL.md、类型定义、数据采集、权重配置
- [ ] **SHARED-02**: 飞书CLI数据采集团装 — 封装 `lark-cli okr` 命令，获取OKR周期/目标/关键结果/对齐/指标数据
- [ ] **SHARED-03**: Git数据采集模块 — 先读取本地IDE git配置获取权限，获取不到再询问用户
- [ ] **SHARED-04**: 4类岗位权重配置 — 研发、产品、测试、管理的差异化评分权重
- [ ] **SHARED-05**: 数据汇总引擎 — 聚合多源数据，生成评分建议供人类参考（非自动评分）
- [ ] **SHARED-06**: 证据匹配器 — 验证用户提供的材料链接与KR的相关性
- [ ] **SHARED-07**: 产品经理证据采集 — 通过飞书CLI搜索用户创建/参与编辑的文档（识别"产品需求文档"/"PRD"标志），收集会议纪要文档，按项目关键词搜索聊天记录
- [ ] **SHARED-08**: 研发证据采集 — 通过飞书CLI搜索技术文档，Git代码相关性分析，迭代表排期任务交付情况
- [ ] **SHARED-09**: 测试证据采集 — 通过飞书CLI搜索测试用例会议纪要、测试用例文档、测试结果文档、Bug提交文档
- [ ] **SHARED-10**: 管理证据采集 — 通过飞书CLI搜索会议决策文档、周报、管理相关文档

### Skill 1: OKR目标设定专家 (GOAL)

- [x] **GOAL-01**: 收集背景信息 — 获取用户身份、岗位说明书、往期OKR分析（历史完成度、重复目标、设定习惯）
- [ ] **GOAL-02**: SMART验证 — 5维度检查（Specific/Measurable/Achievable/Relevant/Time-bound），输出"通过/问题/建议"格式
- [ ] **GOAL-03**: 对齐检查 — 区分贡献型vs依赖型对齐，验证与上级OKR的关联
- [ ] **GOAL-04**: 修改建议与用户确认 — 基于SMART和对齐检查输出具体建议，用户确认后发布

### Skill 2: OKR过程跟进专家 (TRACK)

- [ ] **TRACK-01**: 双周定时触发机制 — 飞书机器人定时推送，提醒用户更新OKR进度
- [ ] **TRACK-02**: 数据采集 — 获取 OKR 系统内部数据（完成度、备注、KR 进展记录）。Phase 3 范围：仅飞书 OKR 数据，Git 提交记录和任务完成情况延期至后续阶段（见 D-10/D-11）
- [ ] **TRACK-03**: 进展对比与风险识别 — 对比上次KR进度，识别2级风险（有进展🟢 / 无进展🔴）
- [ ] **TRACK-04**: 提醒生成与辅导建议 — 生成进展提醒消息，附风险暴露列表和改进建议

### Skill 3: OKR评审评分专家 (REVIEW)

- [ ] **REVIEW-01**: 材料收集 — 获取用户OKR自述文档（飞书文档链接）、案例链接、达成情况自述
- [ ] **REVIEW-02**: 数据验证 — 自动化采集飞书会议/文档/聊天/Git/任务/人效数据
- [ ] **REVIEW-03**: 证据匹配与验证 — 验证链接可访问性、创建者匹配、时间范围、关键词相关性、数据一致性
- [ ] **REVIEW-04**: 评分计算 — 应用难度40%+努力度40%+完成度20%公式，按岗位权重计算
- [ ] **REVIEW-05**: 用户自述文档解析 — 解析非结构化文档（含执行摘要、OKR卡片、补充表格、截图、附录链接）
- [ ] **REVIEW-06**: 评审报告生成 — 输出评分结果、材料支撑清单、优势与不足分析、往期对比、下季度建议

### 集成需求 (INTEG)

- [ ] **INTEG-01**: 人效数据云文档解析 — 解析PMO录入的云文档（含整体评价、产品/研发/测试人效概览、沟通建议）
- [ ] **INTEG-02**: 截图解析模块 — 解析用户自述文档中的截图内容，提取证据信息
- [ ] **INTEG-03**: 集成测试 — 3个Skill端到端流程验证，使用真实OKR案例测试

## v2 需求（延期）

## 明确排除

- **完整KPI评分计算** — OKR Skill只管理20%主观任务，60%客观人效+质量分数由人类完成
- **价值观评分** — 主管直接评分，不需要Skill支持
- **Git邮箱映射配置** — 改为先读本地IDE git配置
- **4级风险分级** — 简化为2级（有进展/无进展）

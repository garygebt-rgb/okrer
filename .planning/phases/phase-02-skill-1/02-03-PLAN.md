Create `~/.claude/skills/okr-goal-setting/workflows/step4-generate-suggestions.md` — the modification suggestion generation workflow.

This file guides the Claude Code agent through generating concrete, actionable suggestions based on the SMART analysis (Step 2) and alignment check (Step 3) results.

Required content:

1. **Input**: 
   - SMART validation results from Step 2 (dimension-by-dimension analysis with results)
   - Alignment check results from Step 3 (contributing/dependent alignments with follow-ups)
   - User's draft Objective title and description
   - Historical OKR analysis from Step 1 (for context on user's patterns)

2. **Suggestion generation rules**:
   a. For each SMART dimension marked as "问题", generate 1-2 specific rewrite suggestions using the examples already provided in Step 2's analysis. Do NOT generate generic advice — use the concrete rewrite examples from Step 2.
   b. For each SMART dimension marked as "建议", provide the specific improvement action (e.g., "添加具体数值指标" for Measurable).
   c. For 贡献型 alignments, suggest how to quantify the contribution (e.g., "建议在关键结果中添加可衡量的贡献指标").
   d. For 依赖型 alignments, suggest dependency management actions (e.g., "建议与 {owner} 确认交付时间表，并在关键结果中添加里程碑节点").
   e. If the user's historical pattern shows "overestimate" (average score > 0.8), suggest: "根据往期数据，你的目标完成率偏高，建议适当提高挑战难度。"
   f. If the user's historical pattern shows "underestimate" (average score < 0.5), suggest: "根据往期数据，你的目标完成率偏低，建议适当降低目标难度或增加资源。"

3. **Output structure**:
   a. **SMART改进建议** section: For each dimension with issues, show:
      - 原始描述: {original text}
      - 问题: {specific issue}
      - 建议改写: {rewritten version}
   b. **对齐改进建议** section: For each alignment issue:
      - 类型: 贡献型/依赖型
      - 建议: {specific action}
   c. **综合建议** section: 1-2 sentences summarizing the overall recommendation based on historical patterns.

4. **Output format** (D-02): All output is plain text + Markdown tables. Example:
```
## SMART改进建议

| 维度 | 原始描述 | 建议改写 |
|------|----------|----------|
| Measurable | 提升系统稳定性 | SLO 达到 99.9%，月度 P0 故障 ≤ 1 次 |

## 对齐改进建议

- **依赖型**：建议与前端团队确认重构交付时间，在 KR 中添加「3月15日前完成 API 对接」里程碑
```

5. **Continue prompt** (D-01): End with "是否继续到 Step 5 (用户确认)? 回复'继续'。"

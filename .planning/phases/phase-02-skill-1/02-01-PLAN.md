1. **Input required from user**: `userID` — the user's Feishu user ID.

3. **Execution procedure** (the agent should do these in order):
   a. **Get user identity**: Call `lark-cli okr cycle-list --user-id {userID}` to fetch the user's OKR cycle list. If this fails, display error and ask user to verify their userID.
   b. **Identify job category**: Extract department/job info from the OKR system response. Map to one of 4 categories: 研发 (DEV), 产品 (PRODUCT), 测试 (QA), 管理 (MANAGEMENT). If unable to determine, default to asking the user.

   d. **Fetch historical cycles**: For each completed or archived cycle, call `lark-cli okr cycle-detail --cycle-id {cycleId}` to get full objective data.
   e. **Analyze historical patterns**: Compute and display:
      - **未完成目标**: List objectives with score < 0.7, showing title, cycle name, and final score.
      - **重复目标**: Group objectives by title similarity (same or very similar titles across cycles), showing title and occurrence count.
      - **设定习惯**: Calculate average score across all historical objectives. If avg > 0.8 → "overestimate" (目标设定偏容易), if avg < 0.5 → "underestimate" (目标设定偏保守), if 0.5-0.8 → "balanced" (目标设定合理).
   f. **Display summary**: Output a Markdown table showing:
      | 指标 | 值 |
      |------|-----|
      | 历史周期数 | N |
      | 未完成目标数 | N |
      | 重复目标数 | N |
      | 平均得分 | X.XX |
      | 设定习惯 | overestimate/underestimate/balanced |
      | 岗位类型 | 研发/产品/测试/管理 |

Create step1-trigger.md with the following workflow structure:

**Title:** Step 1: 触发检查 (Trigger & Auth Check)

**Inputs:** User's userID (auto-detected from lark-cli auth or provided by user)

**Steps:**

1. **Verify lark-cli authentication:**
   - Run `lark-cli auth status` to check if user is authenticated
   - If not authenticated: guide user through `lark-cli auth login`
   - Verify required scope: `okr:okr.content:readonly`

2. **Identify current OKR cycle:**
   - Run `lark-cli okr cycle-list --user-id {userId}` via data-collector's fetchCycles()
   - Find the first cycle with status = "published" and not "completed"
   - If no active cycle found: report error and stop
   - Record cycleId for downstream steps

3. **Load existing snapshot (if any):**
   - Check file: ~/.claude/skills/okr-process-tracking/snapshots/{userId}-{cycleId}.json
   - If file exists: parse as ProgressSnapshot
   - If file does not exist: this is first run — set snapshot = null

4. **Smart skip check (D-17, Resolved Q3):**
   - If snapshot exists AND snapshot.lastReminderTimestamp exists:
     - Get current KR update_time values from cycle detail (each KR has update_time field)
     - If ANY KR has update_time > lastReminderTimestamp: output "智能跳过：用户在上次提醒后已更新 OKR" and stop the workflow
       - Reason (Resolved Q3): Even if score didn't change, updating notes/content shows user engagement — no need to remind
     - Otherwise (no KR updated since last reminder): proceed to step 2
   - If snapshot is null (first run): skip this check, proceed to step 2

5. **First run detection:**
   - If no snapshot exists: note "首次运行，将建立基线快照" — no risk alert will be generated this time
   - Save this flag for step 3

6. **User confirmation:**
   - Output: current cycle info (name, date range, number of objectives)
   - Output: snapshot status (first run OR last reminder date)
   - Ask: "是否继续下一步（数据采集）？"

**Output:** userId, cycleId, snapshot (or null), isFirstRun boolean
  </action>

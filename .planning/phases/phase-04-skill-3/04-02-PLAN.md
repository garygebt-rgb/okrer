# Phase 04 Plan 02: Data Validation + Evidence Matching + Score Calculation

**Workflows for automated data validation (Step 2), 5-dimension evidence matching (Step 3), and weighted score calculation (Step 4) with difficulty/effort/completion dimensions**

## Task Breakdown

### Task 1: Create Step 2 data validation workflow

Create `~/.claude/skills/okr-review-scoring/workflows/step2-data-validate.md` with:

**Input:** Parsed narrative doc from Step 1 (okrCards, appendixLinks, userId, quarter)

**Execution Steps:**
1. Fetch current quarter OKR data via `lark-cli okr +cycle-detail`
   - Extract actual KR scores (0-1 range) from Feishu OKR system
   - Compare system scores with user-claimed scores in narrative doc
2. Fetch historical OKR data for period comparison
   - Previous quarter OKRs via `lark-cli okr +cycle-list`
   - Extract trend data (scores, completion rates)
3. Fetch Git commit records via `okr-shared/data-collector.ts`
   - Analyze commits within quarter time range
   - Calculate: total commits, files changed, lines added/removed
   - Assess KR relevance of commits (by commit message keywords)
4. Fetch efficiency data from PMO cloud doc via `lark-cli docs +fetch`
   - Parse PMO document for user's efficiency metrics
   - LLM extract: task completion rate, delivery time, quality indicators
5. Fetch quality data from Feishu wiki via `lark-cli wiki`
   - Get quality metrics (bug count, test coverage, etc.)
6. Compile validation summary table:
   - OKR system data vs narrative claims (match/mismatch)
   - Git activity summary
   - Efficiency data summary
   - Quality data summary
   - Flag any discrepancies

**Output Format:**
- Data validation summary table (data source, status, key findings)
- Discrepancy list (if any): narrative claim vs system data
- Continue prompt: "确认数据验证完成，输入'继续'进入证据匹配"

**Error Handling:**
- If lark-cli auth fails: guide user through re-authentication
- If PMO doc not found: note as "人效数据不可用", continue without it
- If wiki data not available: note as "质量管理数据不可用", continue
- If historical OKRs unavailable: note as "往期数据不可用", skip period comparison

**Data Type References:**
- `OKRCycle`, `Objective`, `KeyResult` from `okr-types.ts`
- `GitCommitRecord` from `data-collector.ts`

**Security Notes:**
- All data fetched scoped to authenticated user's permissions
- Discrepancies displayed for informational purposes only — LLM scoring considers context

**Continue Prompt:**
> 数据验证完成。已从 OKR 系统获取实际数据，从 Git 获取提交记录，从 PMO 获取人效数据。发现 X 处差异。输入"继续"进入下一步：证据匹配。

### Task 2: Create Step 3 evidence matching workflow

Create `~/.claude/skills/okr-review-scoring/workflows/step3-evidence-match.md` with:

**Input:** Appendix links from Step 1, validated data from Step 2

**Execution Steps:**
1. For each evidence link in the narrative doc:
   a. Verify link accessibility via `lark-cli docs +fetch <url>`
   b. Check creator matches user (via Feishu doc metadata)
   c. Verify document creation/update time within quarter range
   d. Assess keyword relevance to KR (LLM analysis)
   e. Check data consistency with system data (Step 2 findings)
2. Use `EvidenceMatcher` from `okr-shared/evidence-matcher.ts`:
   - 5-dimension matching: creator, time, keyword, URL, consistency
   - Output per-link relevance score (0-1)
3. For Git evidence (commit records):
   - Assess relevance of commits to claimed KR achievements
   - Calculate: relevant commits / total commits ratio
4. For PMO efficiency data:
   - Verify consistency with self-reported achievements
5. Compile evidence summary table:
   - Per-link: URL, accessible, creator match, time match, relevance score
   - Overall: total links, accessible count, average relevance

**Output Format:**
- Evidence matching summary table (per-link results + overall statistics)
- Flagged items: inaccessible links, low-relevance evidence, inconsistent claims
- Continue prompt: "确认证据匹配完成，输入'继续'进入评分计算"

**Error Handling:**
- If link inaccessible: mark as "无法验证", continue with next link
- If multiple links fail: warn user, suggest manual evidence submission
- If evidence matcher produces low scores across board: note in summary, proceed to scoring

**Data Type References:**
- `EvidenceMatchResult` from `evidence-matcher.ts`
- `EvidenceMatchDimension` from `okr-types.ts`

**Security Notes:**
- Only fetch documents accessible to authenticated user
- Do not attempt to access documents outside user's permission scope

**Continue Prompt:**
> 证据匹配完成。共验证 X 个证据链接，平均相关度 Y%。Z 个链接无法访问。输入"继续"进入下一步：评分计算。

### Task 3: Create Step 4 score calculation workflow

Create `~/.claude/skills/okr-review-scoring/workflows/step4-score-calc.md` with:

**Input:** Validated data (Step 2), evidence matching results (Step 3), job category (Step 1), KR scores from OKR system

**Execution Steps:**

**Dimension 1: Difficulty Assessment (40%)**
1. LLM assesses each KR's difficulty across 5 dimensions (1-5 scale each):
   - 技术复杂度: 是否涉及新技术、架构变更、跨系统集成
   - 资源投入: 所需人力、时间、预算
   - 时间压力: 交付期限是否紧张
   - 创新性要求: 是否需要首创方案、无先例可循
   - 跨部门协作: 依赖多少外部团队
2. Calculate per-KR difficulty score: average of 5 dimensions → 0-100
3. Calculate overall difficulty: weighted average across all KRs (by importance)

**Dimension 2: Effort Assessment (40%)**
1. Calculate evidence-based effort metrics:
   - Evidence count score: number of valid evidence items (normalized to 0-100)
   - Update frequency score: how frequently OKR was updated during quarter (normalized)
   - Git activity score: relevant commits, code changes during quarter (normalized)
2. Combine: evidence_count × 0.3 + update_frequency × 0.3 + git_activity × 0.4
3. Result: effort score 0-100

**Dimension 3: Completion Assessment (20%)**
1. Use actual KR scores from Feishu OKR system (0-1 range)
2. Convert to 0-100 scale: score × 100
3. Calculate average completion across all KRs

**Final Score Calculation:**
1. Load job-specific weights from `okr-shared/job-weights.ts` (for reference)
2. Apply formula: total = difficulty × 0.4 + effort × 0.4 + completion × 0.2
3. Output: detailed score breakdown per dimension + per-KR scores

**Output Format:**
- Score breakdown table:
  | 维度 | 得分 | 权重 | 加权分 |
  |------|------|------|--------|
  | 难度 | XX/100 | 40% | XX |
  | 努力度 | XX/100 | 40% | XX |
  | 完成度 | XX/100 | 20% | XX |
  | **总分** | | | **XX/100** |
- Per-KR score breakdown table
- Scoring methodology notes (transparent reasoning)
- Continue prompt: "确认评分计算完成，输入'继续'进入自述文档解析"

**Error Handling:**
- If difficulty assessment criteria unclear for a KR: use conservative estimate, flag for manual review
- If evidence count is zero: effort score defaults to 0, warn user
- If KR scores not available from OKR system: completion defaults to 0, warn user

**Data Type References:**
- `JobCategory`, `JobWeightConfig` from `job-weights.ts`
- `KeyResult` from `okr-types.ts`

**Security Notes:**
- Scores are suggestions for human reviewer — final decision is human's
- Clearly label all scores as "建议评分" not "最终评分"

**Continue Prompt:**
> 评分计算完成。总分 XX/100（难度 XX，努力度 XX，完成度 XX）。此为建议评分，最终评分由人类评审决定。输入"继续"进入下一步：自述文档解析。

# Phase 04 Plan 03: Detailed Doc Parsing + Report Generation + Template

**Step 5 performs deep LLM analysis of narrative documents with screenshot evidence extraction; Step 6 generates structured review report using template with explicit user confirmation; review report template created for consistent output**

## Task Breakdown

### Task 1: Create Step 5 detailed document parsing workflow

Create `~/.claude/skills/okr-review-scoring/workflows/step5-doc-parse.md` with:

**Input:** Parsed narrative doc from Step 1, validated data from Step 2, evidence matching results from Step 3, scores from Step 4

**Execution Steps:**

**5.1 Deep Content Analysis**
1. Analyze executive summary for completeness:
   - Does it cover all OKRs set at quarter start?
   - Are key achievements clearly stated?
   - Is there honest acknowledgment of shortfalls?
2. Cross-reference narrative claims with system data (Step 2):
   - For each claimed achievement, verify against OKR system actual scores
   - Flag overstatements (claimed > actual)
   - Flag understatements (claimed < actual — user may be modest)
3. Identify gaps:
   - OKRs with no narrative coverage
   - Claims with no supporting evidence
   - Discrepancies between narrative and system data

**5.2 Screenshot Analysis**
1. For each screenshot in the narrative doc:
   - Use Claude vision to analyze the screenshot
   - Extract: what it shows, actionable data points, evidence type
   - Assess: is this usable as evidence? (confidence score)
2. Compile screenshot evidence summary:
   - Usable screenshots count and key findings
   - Unusable screenshots with reasons (blurry, irrelevant, etc.)

**5.3 Narrative vs Evidence Gap Analysis**
1. Compare narrative claims against collected evidence:
   - Claims with strong evidence support
   - Claims with weak/no evidence
   - Evidence not mentioned in narrative
2. Generate gap analysis:
   - Over-represented areas (lots of narrative, little evidence)
   - Under-represented areas (strong evidence, little narrative)
3. LLM assessment of narrative honesty and completeness

**Output Format:**
- Deep analysis summary table:
  | 分析维度 | 发现 |
  |----------|------|
  | 执行摘要完整性 | 完整/部分/缺失 |
  | 声称 vs 实际一致性 | X 处一致, Y 处夸大, Z 处保守 |
  | 叙事空白 | N 个 OKR 未提及 |
  | 截图可用性 | X/Y 张可用 |
  | 总体诚实度 | 高/中/低 |
- Gap analysis list (specific items)
- Continue prompt: "确认自述文档解析完成，输入'继续'进入报告生成"

**Error Handling:**
- If Claude vision fails for screenshots: mark as "无法解析，需要人工查看"
- If narrative doc is extremely brief: note "自述内容较少，建议补充详细说明"
- If no discrepancies found: note "自述内容与系统数据一致"

**Data Type References:**
- `ScreenshotAnalysis` from `screenshot-parser.ts`
- `ParsedNarrativeDoc` from `doc-parser.ts`
- `KeyResult` from `okr-types.ts`

**Security Notes:**
- Screenshot analysis limited to professional content (no personal data extraction)
- Gap analysis presented neutrally — not as accusations

**Continue Prompt:**
> 自述文档解析完成。发现 X 处声称与实际一致，Y 处差异。Z 张截图中 W 张可用。输入"继续"进入下一步：报告生成。

### Task 2: Create Step 6 report generation workflow

Create `~/.claude/skills/okr-review-scoring/workflows/step6-report-gen.md` with:

**Input:** All outputs from Steps 1-5 (materials, validated data, evidence, scores, doc analysis)

**Execution Steps:**
1. Compile all data into structured review report using template
2. Generate report sections (see template below):
   - Header: employee name, quarter, job category, date
   - Score results: difficulty, effort, completion, total (with breakdown)
   - Evidence list: all verified evidence with accessibility and relevance
   - Strengths and weaknesses: LLM assessment based on all data
   - Period comparison: current quarter vs previous (if available)
   - Next-quarter suggestions: specific, actionable recommendations
3. Preview full report for user review
4. User confirmation (3-way choice):
   - **确认保存**: Save report to `reports/{userId}-{quarter}.md`, display confirmation
   - **修改**: Allow user to request specific changes, regenerate report
   - **取消**: Exit without saving, display exit message

**Output Format:**
- Full review report preview (using template structure)
- 3-way user choice prompt
- Save confirmation message (if confirmed)

**Error Handling:**
- If report generation fails: display error, suggest manual report creation
- If file save fails: display content for manual copy-paste
- If user chooses "修改": loop back to regenerate with specified changes

**Data Type References:**
- All types from previous steps
- `JobCategory` from `okr-types.ts`

**Security Notes:**
- Report contains sensitive performance data — saved to local directory only
- All scores explicitly labeled as "建议评分 — 最终评分由人类评审决定" (T-04-01)
- Report includes disclaimer: "本评分报告由系统自动生成，仅供参考，不构成最终绩效评价"

**Continue Prompt (workflow end):**
> 评审报告已保存至 `reports/{userId}-{quarter}.md`。
> 总分: XX/100（难度 XX，努力度 XX，完成度 XX）。
> 此为建议评分，最终评分由人类评审决定。
>
> okr-review-scoring 工作流完成。如需再次评审，重新运行此 Skill。

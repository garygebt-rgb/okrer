# Step 1: 材料收集

**输入:** 用户提供自述文档 URL（飞书文档），Step 0 已读取的 Skill 2 周报快照

## 执行步骤

### 1. 读取 Skill 2 周报快照

检查本地快照目录：`~/.claude/skills/okr-process-tracking/snapshots/{userId}-{cycleId}/`

- 查找所有 `weekly-*.md` 文件
- 按日期排序，读取最近 1-4 份周报
- 提取：每个 O/KR 的得分变化趋势、风险识别结果、辅导建议

**若无快照存在：** 标记为"过程跟踪数据不可用"，继续后续步骤，但努力度评分可能受影响。

### 2. 验证文档 URL

1. 检查用户提供的 URL 格式是否有效（飞书文档链接）
2. 如果 URL 无效，引导用户提供正确的飞书文档链接

### 3. 获取文档内容

执行 `lark-cli docs +fetch <url>` 获取文档内容。

```bash
lark-cli docs +fetch "<用户提供文档URL>"
```

处理错误：
- 如果命令失败（权限不足/链接过期），告知用户具体原因
- 如果返回空内容，提示用户检查文档是否有内容或是否有访问权限
- 降级方案：引导用户手动粘贴文档内容

### 4. LLM 提取关键部分

使用 LLM 语义理解从文档内容中提取以下关键部分：

1. **执行摘要** — 用户对本季度工作的整体概述
2. **OKR 卡片** — 每个 Objective 及其 KeyResults 的自述完成情况
   - 目标标题
   - 关键结果描述
   - 用户声称的完成度（0-1 或百分比）
   - 支撑证据描述
3. **附录链接** — 用户提供的证据链接（文档、Git 仓库、仪表盘等）
4. **截图引用** — 文档中的截图位置或标识

### 5. 识别用户岗位

通过 `lark-cli okr +cycle-list` 获取用户的 OKR 周期列表，从返回数据中识别用户的部门/岗位信息。

自动匹配 4 类岗位（研发/产品/测试/管理）。如果无法自动识别，询问用户选择岗位类型。

### 6. 识别评审周期

从用户的 OKR 周期列表中识别当前需要评审的周期（通常是最近一个已完成的周期，status = completed）。

如果存在多个已完成周期，让用户确认要评审的周期。

### 7. 显示提取摘要

输出材料收集摘要表格，供用户确认。

## 输出格式

```
## 材料收集完成

### 文档信息
| 项目 | 值 |
|------|-----|
| 文档链接 | [URL] |
| 文档状态 | 已获取/无法访问 |

### 提取内容
| 部分 | 状态 | 数量 |
|------|------|------|
| 执行摘要 | 已提取/缺失 | 1 |
| OKR 目标 | 已提取/缺失 | X 个 |
| 关键结果 | 已提取/缺失 | Y 个 |
| 证据链接 | 已提取/缺失 | Z 个 |
| 截图引用 | 已提取/缺失 | W 个 |

### 用户信息
| 项目 | 值 |
|------|-----|
| 岗位 | [研发/产品/测试/管理] |
| 评审周期 | [2026-Q1] |
| 周期状态 | 已完成 |
```

## 数据类型引用

- `Objective`, `KeyResult` from `okr-types.ts`
- `JobCategory` from `okr-types.ts`
- `OKRCycle`, `CycleStatus` from `okr-types.ts`

## 安全说明

- 文档内容通过认证的 lark-cli 获取，仅限当前用户权限范围内的数据
- 解析结果仅在当前会话中显示，报告保存前不持久化

## 错误处理

- **文档 URL 无效**: 引导用户纠正 URL
- **文档内容为空**: 降级为手动输入模式，提示用户粘贴内容
- **岗位无法识别**: 询问用户从 4 类岗位中选择
- **无已完成周期**: 提示用户当前无已完成的可评审周期

## 继续提示

> 材料收集完成。共提取到 X 个 OKR 目标、Y 个关键结果、Z 个案例链接、W 张截图。输入"继续"进入下一步：数据验证。

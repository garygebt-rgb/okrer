# Step 4: 生成修改建议

**目标：** 基于 Step 2 的 SMART 验证结果和 Step 3 的对齐检查结果，生成具体的、可操作的修改建议，帮助用户改进 OKR 目标。

**前置条件：** Step 2（SMART 验证）和 Step 3（对齐检查）已完成

**下一步：** Step 5 -- 用户确认

## 输入

- **Step 2 SMART 验证结果：** 5 个维度的分析结果（通过/问题/建议），每个维度的当前状态描述、问题原因、改写示例
- **Step 3 对齐检查结果：** 贡献型对齐列表、依赖型对齐列表、未覆盖上级目标列表
- **用户草稿 Objective 的标题和描述：** 用户最初输入的 OKR 目标
- **Step 1 历史 OKR 分析数据：** 平均得分、设定习惯（目标设定偏容易/偏保守/合理）、岗位类型

## 执行步骤

### 1. 收集并整理输入数据

从前面步骤的输出中获取：

a. 读取 Step 2 的 SMART 验证汇总表，提取每个维度的结果（通过/问题/建议）

b. 读取 Step 3 的对齐检查汇总，提取贡献型对齐数量、依赖型对齐数量、未覆盖上级数量

c. 读取 Step 1 的历史分析报告，提取：
   - 平均得分（averageScore）
   - 设定习惯（tendency）：overestimate（>0.8）/ underestimate（<0.5）/ balanced（0.5-0.8）
   - 岗位类型（jobCategory）

d. 获取用户草稿的目标标题和描述

### 2. 生成 SMART 改进建议

**规则：** 仅对标记为"问题"和"建议"的维度生成建议。"通过"的维度不生成建议。

#### 2.1 对"问题"维度的建议（生成 1-2 条具体改写）

对于每个标记为"问题"的 SMART 维度：

- 使用 Step 2 中已经提供的具体改写示例（不要生成新的通用建议）
- 改写建议必须直接引用 Step 2 分析中给出的改写版本

**输出格式（Markdown 表格）：**

```
## SMART改进建议

| 维度 | 原始描述 | 问题 | 建议改写 |
|------|----------|------|----------|
| Measurable | 提升系统稳定性 | 缺少量化指标，无法判断何时算"稳定" | SLO 达到 99.9%，月度 P0 故障 ≤ 1 次 |
| Time-bound | 完成 API 升级 | 没有明确的截止时间 | 3月31日前完成 v2.0 API 上线 |
```

#### 2.2 对"建议"维度的建议（提供具体改进行动）

对于每个标记为"建议"的 SMART 维度：

- 提供具体的改进动作（如"添加具体数值指标"、"增加里程碑节点"）
- 如果 Step 2 中已提供改写示例，一并引用

**输出格式：**

```
### 建议改进维度

- **{维度名}**：{具体改进动作}
  参考改写：{Step 2 中的改写示例（如有）}
```

#### 2.3 对"通过"维度的处理

- 不生成建议
- 在输出中简要标注"无改进建议"

### 3. 生成对齐改进建议

#### 3.1 贡献型对齐建议

对于每个贡献型对齐关系，建议如何量化贡献：

**输出格式：**

```
### 贡献型对齐建议

- 你的目标「{objective title}」有助于 {owner} 的目标「{target title}」达成
  建议：在关键结果中添加可衡量的贡献指标，例如"通过优化 CI/CD 流程，使团队构建时间缩短 30%"
```

#### 3.2 依赖型对齐建议

对于每个依赖型对齐关系，建议依赖管理行动：

**输出格式：**

```
### 依赖型对齐建议

- 你的目标「{objective title}」需要 {owner} 的「{target title}」完成后才能推进
  建议：与 {owner} 确认交付时间表，并在关键结果中添加里程碑节点，例如"3月15日前完成 API 对接"
```

#### 3.3 未覆盖上级目标建议

如果存在未覆盖的上级目标：

```
### 未覆盖上级目标

- 上级目标「{target title}」（负责人：{owner}）未建立对齐关系
  建议：确认是否需要为此上级目标设定子目标，如需则在目标描述中明确对齐关系
```

### 4. 生成综合建议（基于历史模式）

根据 Step 1 的用户历史模式分析，生成 1-2 句综合建议：

#### 4.1 目标设定偏容易（averageScore > 0.8）

```
## 综合建议

根据往期数据（平均得分 {averageScore.toFixed(2)}），你的目标完成率偏高。
建议适当提高挑战难度，例如增加一个具有挑战性的关键结果，或将现有目标的量化指标提高 10-20%。
```

#### 4.2 目标设定偏保守（averageScore < 0.5）

```
## 综合建议

根据往期数据（平均得分 {averageScore.toFixed(2)}），你的目标完成率偏低。
建议适当降低目标难度或增加资源投入。考虑将目标拆分为阶段性里程碑，先确保第一阶段可达成。
```

#### 4.3 目标设定合理（0.5 <= averageScore <= 0.8）

```
## 综合建议

根据往期数据（平均得分 {averageScore.toFixed(2)}），你的目标设定难度合理。
请重点参考上方的 SMART 改进建议和对齐改进建议，完善目标描述后即可提交。
```

### 5. 汇总输出

将以上所有建议整合为完整的修改建议报告。

## 输出格式

```
## 修改建议

### SMART改进建议

| 维度 | 原始描述 | 问题 | 建议改写 |
|------|----------|------|----------|
| {dimension} | {original text} | {issue} | {rewritten version} |

（仅列出"问题"和"建议"维度的建议；"通过"维度不列出）

### 对齐改进建议

**贡献型对齐：**
- {suggestion for contributing alignment}

**依赖型对齐：**
- {suggestion for dependent alignment}

（如有未覆盖上级目标，一并列出）

### 综合建议

{1-2 sentences based on historical pattern analysis}
```

## 数据类型引用

本步骤使用以下 `okr-shared` 类型：

- `SmartDimension` -- SMART 5 维度枚举（来自 `okr-types.ts`）
- `Objective` -- 目标结构（来自 `okr-types.ts`）
- `AlignmentType` -- 对齐类型枚举（来自 `okr-types.ts`）
- `Alignment` -- 对齐关系结构（来自 `okr-types.ts`）
- `PreviousOKRAnalysis` -- 历史分析数据（来自 `okr-types.ts`）

## 安全注意

- 生成的修改建议仅为**建议性质**，不代表强制要求（T-02-08）
- 建议在输出中明确标注"以下为建议，最终目标由你决定"
- 不修改任何飞书系统数据，仅生成文本建议

# Step 2: 数据验证

**输入:** Step 1 解析的自述文档（okrCards、appendixLinks、userId、quarter）

## 执行步骤

### 1. 获取当前季度 OKR 实际数据

执行 `lark-cli okr +cycle-detail <cycleId>` 获取当前评审周期的完整 OKR 数据。

```bash
lark-cli okr +cycle-detail --cycle-id "<cycleId>"
```

- 提取各 KR 的实际 score 值（0-1 范围）
- 与 Step 1 中用户声称的完成度进行对比
- 记录一致/不一致的 KR

### 2. 获取往期 OKR 数据（用于对比）

执行 `lark-cli okr +cycle-list --user-id <userId>` 获取用户的 OKR 周期列表。

```bash
lark-cli okr +cycle-list --user-id "<userId>"
```

- 识别上一个已完成周期
- 提取往期各 O/KR 的 score 值
- 用于 Step 6 报告中的往期对比

### 3. 获取 Git 提交记录

通过 `okr-shared/data-collector.ts` 中的 Git 数据采集函数获取：

1. 检测本地 IDE Git 配置（VS Code / JetBrains）
2. 在季度时间范围内分析 Git 提交活动
3. 统计：总提交数、文件变更数、代码行增减
4. 按提交消息关键词评估与 KR 的相关性

**如果 Git 配置检测失败：**
> ⚠️ 未能获取 Git 提交记录。如需完整评审（努力度评分需要 Git 数据），请提供 Git 仓库 URL 和你的邮箱地址。

### 4. 获取人效数据（PMO 云文档）

如果用户在 Step 1 提供了 PMO 人效数据文档链接：

```bash
lark-cli docs +fetch "<PMO文档URL>"
```

- 使用 LLM 提取结构化指标：任务完成率、交付时间、质量指标
- 如果文档不可获取：
> ⚠️ 人效数据不可用。如需完整评审，请提供 PMO 人效文档链接。

### 5. 获取质量管理数据

执行 `lark-cli wiki` 获取飞书知识库中的质量管理数据。

- 获取 bug 数量、测试覆盖率等质量指标
- 如果 wiki 数据不可用：
> ⚠️ 质量管理数据不可用。如需完整评审，请配置飞书知识库或提供质量管理文档链接。

### 6. 汇总验证摘要

整合以上所有数据源，输出验证摘要表格。

## 输出格式

```
## 数据验证完成

### 数据源状态
| 数据源 | 状态 | 关键发现 |
|--------|------|----------|
| OKR 系统 | 已获取 | X 个目标，Y 个关键结果 |
| 往期 OKR | 已获取/不可用 | [趋势信息] |
| Git 提交 | 已获取/不可用 | Z 次提交，W 次与 KR 相关 |
| 人效数据 | 已获取/不可用 | [关键指标] |
| 质量管理 | 已获取/不可用 | [质量指标] |

### 声称 vs 实际对比
| KR | 声称完成度 | 实际 score | 状态 |
|----|------------|-----------|------|
| KR 1 | X% | Y | 一致/夸大/保守 |
| KR 2 | X% | Y | 一致/夸大/保守 |

### 差异列表
| # | 差异描述 | 类型 |
|---|----------|------|
| 1 | [具体差异] | 夸大/保守/遗漏 |

### 数据补充建议
- [ ] 如需更准确的努力度评分，请提供 Git 仓库信息
- [ ] 如需完整评审报告，请提供 PMO 人效文档或质量管理数据链接
```

## 数据类型引用

- `OKRCycle`, `Objective`, `KeyResult` from `okr-types.ts`
- `GitActivity` from `okr-types.ts`
- `CycleStatus` from `okr-types.ts`

## 安全说明

- 所有数据通过认证用户的权限范围获取
- 差异信息仅供 LLM 评分时参考，不作为最终判断

## 错误处理

- **lark-cli 认证失败**: 引导用户重新执行 `lark-cli auth login`
- **PMO 文档不可获取**: 引导用户提供替代文档链接
- **Wiki 数据不可用**: 引导用户配置知识库或提供文档链接
- **往期 OKR 不可用**: 记录为"往期数据不可用"，跳过对比
- **Git 配置检测失败**: 引导用户提供 Git 仓库 URL 和邮箱

## 继续提示

> 数据验证完成。已从 OKR 系统获取实际数据，从 Git 获取提交记录，从 PMO 获取人效数据。发现 X 处差异。输入"继续"进入下一步：证据匹配。
